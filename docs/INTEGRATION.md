# Встраивание в EKT

На публичной странице https://ekt.kz/about/contacts/ обнаружены ресурсы `/bitrix/`. Версия Bitrix и административная конфигурация не проверялись.

## Виджет

```html
<script defer src="https://ASSISTANT_HOST/widget.js"></script>
```

Замените `ASSISTANT_HOST` настоящим HTTPS-доменом приложения. Скрипт создаёт кнопку и изолированный iframe `/?embed=1`, открываемый по нажатию. Локальный пример: `/embed-demo`.

`EMBED_ALLOWED_ORIGINS=https://ekt.kz,https://www.ekt.kz` ограничивает `frame-ancestors`. Для staging добавьте точный HTTPS-origin; не используйте `*`. Остальные страницы запрещают встраивание. API внутри iframe обращается к собственному origin; открытый CORS не нужен.

На стороне EKT необходимо проверить CSP родительской страницы (`frame-src`), HTTPS reverse proxy/поддомен, sessionStorage в целевых браузерах и маршруты приложения. Все пути frontend абсолютные: для размещения под префиксом нужен согласованный proxy rewrite или отдельный поддомен. MVP не проверялся в административном шаблоне EKT.

## Корзина

`app/cart_actions.py` формирует снимок товара, количества, склада и цены; токен привязан к сессии на 120 секунд. Перед записью повторяются проверки, действия сериализованы блокировкой. Изменившиеся цена/остаток требуют нового подтверждения. `app/cart_provider.py` задаёт границу адаптера.

`LocalCartProvider` пишет только в память. `/cart` открывает ту же корзину в той же вкладке. Штатная корзина `https://ekt.kz/personal/cart/` не меняется.

Для production нужны: разрешённый EKT метод/Bitrix-контроллер корзины, связь с авторизованной или анонимной сессией, проверка прав и CSRF, идемпотентность, повторная проверка цены/остатка, реальный `cart_url`, тестовый контур и правила резервирования. Произвольный AJAX URL публичного сайта не считается согласованным API.

## Менеджер и данные

Телефон, WhatsApp и email проверены на официальной странице контактов. Кнопка открывает соответствующее приложение; сообщение отправляет сам клиент. История не передаётся автоматически. `/api/handoff/*` остаются демонстрационными и возвращают `mode=demo`.

BasicAuth и ключи ИИ находятся на сервере. Для внутренней БД, CRM и истории авторизованных клиентов нужны отдельные доступы партнёра.
